# @biased: repos chosen for maximal AGENT-TYPEABLE compressible mass — a best-case upper bound for the codec, not a real-world average. Report headline efficiency from tasks/diverse-20.txt; use this set to validate the mechanism delivers where it should.
# Argot pilot: the 10 DeepSWE tasks whose repos offer the most compressible mass
# in strings a coding agent would actually type, by `typeable saving` in
# dicts/report.md (2026-07-24), deduplicated to 10 distinct repositories.
#
# This set was re-selected on 2026-07-24. The previous selection ranked on the
# SDK's raw estimatedSavings, which counts every string that repeats in a
# repository. That is dominated by license blocks, fixture YAML, and doc URLs,
# which earn handles but which no agent ever retypes, so the ranking did not
# measure what it claimed to. Measured on the first run where encoding fired:
# of 33 handles the model emitted 7, and every one was whitespace-free, while no
# prose handle was ever emitted.
#
# The old set was mis-selected as a result. It contained psd-tools-blend-range-api
# (rank 95 of 110, 9 characters of reachable mass) and two fastapi tasks at ranks
# 70 and 71, so a set built to show the codec's best case was half filled with
# tasks where it can do essentially nothing. Every task below carries between 836
# and 2434 characters of reachable mass per emission.
#
# These numbers are post-fix. The generator no longer captures prose sentences
# whole, which freed budget for real paths and raised reachable mass across the
# corpus by 22.7% (31,365 -> 38,483 characters). See argot's generate.ts
# looksLikeProse and its regression tests.
#
# THIS SET STILL CANNOT MEASURE A TOKEN DELTA, and the reason is not the ranking.
# Every task here was ranked on `typeable saving`, which is an UPPER bound: it
# counts every handle an agent could type as one it does. The run that measured
# both emitted 8 of 551 handles, so the real expectation is that column times
# 1.45% (`OBSERVED_TYPEABLE_EMISSION_RATE` in aggregate.ts). The best task below,
# at 2434 characters of reachable mass, expects about 35 characters per emission.
#
# Re-derived under the corrected model, as ARGOT-HEADROOM-PROJECTION-OFF-BY-50X
# asked: NO task in this set clears the ~8.15% within-task output-token noise
# floor, and none is close. Raising `tokenBudget` does not help either, because
# the expected ceiling scales with the budget while the floor does not: a 16x
# budget moved it from 0.015% to 0.28%, three orders of magnitude short. The
# ranking is still correct and still worth having, since it is the right ORDER; it
# is the absolute scale that was misread.
#
# So use this set to answer "does the mechanism fire at all" (adoption: `runs that
# encoded`, `handles ever emitted`), which it can answer. Do not use it to produce
# a headline token number, and do not read a token delta off it as a result. A
# workload that could produce one needs a higher EMISSION rate, which is a
# property of the model, the prompt, and the task rather than of dictionary size.
